# effort-router の変更履歴

## 0.9.1 — 2026-10-08

- 修正: 選択肢を出したあとにツールを呼び、短い文（「結果が届いたらお知らせします」など）でターンを終えると、次の「3」を選択として扱わなかった。0.8 系では前ターンの段階を引き継ぎ、0.9.0 では選んだ案の本文なしで判定していた。`turn.complete` の回答はターンの最後のテキストだけなので、最後のテキストに選択肢がなければ、ターンの途中で選択肢を含んでいたテキストから読むようにした。
- 文書: 選択肢の読み取り元を「回答の全文」から「ターンの最後の回答」に改めた。拾わない書式（見出し、隅付き括弧、区切り記号のない形など）を既知の課題に書いた。

## 0.9.0 — 2026-10-08

- 変更: 20文字未満の入力でも、同意の語だけ（「OK」「はい、進めて」「続けて」など）でなければ Haiku で判定するようにした。これまでは「リポジトリ全体を監査して」のような短い依頼も、前の回答が質問で終わっていなければ前ターンの段階を引き継いでいた。短い入力で Haiku を呼ぶ回数が増え、そのぶん待ち時間（約1秒）が増える。
- 修正: 前の回答に番号付きの一覧があると、「OK」が「前の回答の提案を進める依頼」として渡らず、返事の語に判定が引っぱられていた。同意の返事なら、一覧の有無にかかわらず提案を進める依頼として渡すようにした。
- 修正: 質問のあとの「いや、やめて」のような否定の返事を、提案を進める依頼として渡していた。同意の語だけの返事に限るようにした。
- 評価セットに、一覧のあとの「OK」、短い重い依頼、質問のあとの短い別の依頼、否定の返事の4件を足した（36件）。

## 0.8.1 — 2026-10-07

- 修正: 前の回答の質問に「OK」「はい」とだけ返したとき、承認した作業が重くても low と判定されることがあった。返事の語に判定が引っぱられていたため、Haiku には「前の回答が提案した作業を進める依頼」として渡すようにした。選択肢に無い短い入力と、`AskUserQuestion` への自由記述の回答は、これまでどおり本文で判定する。
- 評価セットに、設計の提案に「ＯＫ」と答えるケースを足した（32件）。

## 0.8.0 — 2026-10-07

- 追加: `/effort-router log clear` で判定ログを消せるようにした。
- 変更: 最初のターンは `$.session.model()` でモデルを確かめ、対象外のモデルなら Haiku を呼ばないようにした（これまでは最初のプロンプトだけ判定が走り、効いていない段階をステータスラインに出していた）。
- 変更: 対象外のモデルでは、ステータスラインに `not routed (<モデル>)` と出すようにした。
- 修正: 回答が CRLF の改行でも選択肢を読み取れるようにした。コードブロックの中の番号付きの行を、選択肢として拾わないようにした。
- 文書: README を、概要・導入・使い方・費用とデータ・仕組みの順に組み直した。費用、待ち時間、Haiku に送るデータ、手元に残るデータを明記した。

## 0.7.0 — 2026-10-07

このリポジトリ（ns-mods）で公開した最初の版です。

- 対象は Opus / Sonnet 5.5 以降と Fable / Mythos 5.1 以降。
- 組み込みの `/effort` で変えた値は、そのターン（ターンの合間なら次のターン）だけ設定どおりに動く。

## 0.6 以前

公開前の版です。主な変更は次のとおりです。

- 0.6: 判定基準を4段階（low / medium / high / xhigh）にし、評価セットの期待値を付け直して、xhigh と low のケースを足した。
- 0.4: 前の回答の選択肢と「質問で終わったか」を、次のターン用の信号として保存するようにした。
- 0.3 まで: 番号での選択と短い返事は、判定を呼ばずに前ターンの段階を引き継いでいた。
