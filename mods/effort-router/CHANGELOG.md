# effort-router の変更履歴

## 0.12.1 — 2026-11-21

コードレビューの指摘8件を直した。

- 修正: 実行中のターンの後ろに入力が2件以上並ぶと、2件目以降の出どころ（`origin`）を失っていた。ターンが始まるたびに、控えた入力をすべて捨てていたため。本文の書き出しで見分けられない自動の続き（`auto-continuation`）や中継の報告（`projects-relay` / `observer`）は、依頼として Haiku で判定していた。そのターンの入力と、それより前に届いた入力だけを捨てるようにした。
- 修正: ターンの合間に `/effort` で変えたあと、自分の入力より先に完了通知などがターンを始めると、設定がそのターンで使われてしまい、自分の入力は自動で判定されていた。依頼ではないメッセージのターンも設定どおりに動かし、設定は次の人の入力まで持ち越すようにした。
- 修正: 最初のリクエストの前に終わったターン（判定待ちの間に Esc で止めたときなど）が、次のターン用の信号を空の段階で上書きしていた。次の「続けて」や完了通知が、前の段階ではなくセッションの effort で動いていた。リクエストが1回も無かったターンは、信号を保存しないようにした。
- 修正: 英字1文字で始まるだけの行（`e.g. …`、`C:\Users\…`、`Q: …` と `A: …`）を選択肢と読んでいた。前の回答が選択肢で終わったとみなすので、次の「OK」を前ターンの段階の引き継ぎではなく「提案を進める依頼」として Haiku で判定していた。選択肢のひと続きは、`1` か `a` で始まり、順に2件以上続くものに限った。`01.` `02.` は `1` `2` として読む。
- 修正: 下の層のフックが本文を書き換えた入力の出どころを失っていた。書き換える前の本文だけを控えていたため。入力が入ったあとの本文で控え直す。待機中に届いた入力はターンが入力の途中で始まるので、入ってくる途中の入力が1件だけなら、それをそのターンの入力とする。取り下げられた入力は控えから外す。
- 修正: 完了通知などのターンで `AskUserQuestion` に答えると、`/effort-router log` の行が `asked task notice` になり、どの質問で判定し直したかが分からなかった。判定し直したら、依頼ではないメッセージの種類を外すようにした（`asked <質問の見出し>` と出る）。
- 修正: モデルの版を「メジャー + マイナー ÷ 10」で比べていたので、マイナーが2桁の ID（`claude-sonnet-4-15` なら 5.5）を対象と読んでいた。メジャーとマイナーを別々の整数で比べるようにした。今ある ID では起きない。
- 修正: Bedrock や Google Cloud のモデル ID（`us.anthropic.claude-…`）では、最初のターンの時点でモデルが分からず、対象外のモデルでも Haiku を1回呼び、ステータスラインに段階を出していた（effort の書き換えは起きていなかった）。`claude-` を途中に含む ID も受けるようにした。
- 変更: 選択肢を拾う条件が狭くなった。番号が順に続かない箇条書き（すべて `1.` で書いたものなど）と、1件だけの番号付きの行は、選択肢として拾わない。
- 内部: `route.ts` の `originOf` を `claim` に替えた（そのターンの入力の出どころと、あとのターンに残す入力を返す）。
- 確認: Claude Code 2.1.287 と 2.1.330 で、検査（`claude plugin validate`）とテスト（86件）が通ることを確かめた。型検査は 2.1.330 で通ることを確かめた。実機で入力を並べての確認はしていない。

## 0.12.0 — 2026-11-07

- 修正: サブエージェントの報告（`<agent-message …>`）、plugin からのメッセージ（`The <名前> plugin sent a message:`）、利用上限の解除後の自動の続きを、依頼として Haiku で判定していた。長い報告が「差分のレビュー」「全体の監査」のように読まれ、high / xhigh に偏っていた（#1）。`prompt.submit` が渡す出どころ（`origin`）で依頼かどうかを見分け、依頼でなければ判定せずに前ターンの段階を引き継ぐようにした。出どころが分からないときは、本文の書き出しで見分ける。
- 修正: 人が打った入力でも、`<task-notification>` で始まると完了通知として扱い、判定していなかった。出どころが人の入力なら判定する。
- 修正: 前ターンの段階を引き継ぐとき（完了通知などのメッセージ、「OK」「続けて」のような短い入力、判定の失敗）、途中で引き上げたあとの段階を引き継いでいた。引き継いだターンも長引けばさらに1段上がるので、1回の判定から何段も上がることがあった（#1）。引き上げる前の段階を引き継ぐようにした。
- 修正: バックグラウンドのサブエージェントが自分のターンを始めると（`turn.start` に `agentId` が付く）、メインスレッドのプロンプトとして判定していた。Haiku を余分に呼び、ステータスラインにサブエージェントの段階を出し、それ以降メインスレッドのツールのエラーと `AskUserQuestion` の回答を、サブエージェントのターンに数えていた。サブエージェントのターンには何もしないようにした。
- 変更: ステータスラインとログに、依頼ではないメッセージの種類（`task notice` / `agent message` / `plugin message` / `continuation` / `relayed message`）を出す。
- 確認: `/model` で切り替えた直後のターンを切り替える前のモデルで判断する件（#2）は、0.11.0 で直っている。Claude Code 2.1.319 で、`classic.PostModelSwitch` が解決済みのモデル ID を持って、次のプロンプトより前に届くことを確かめた。
- 文書: 依頼ではないメッセージの見分け方、引き継ぐ段階、Haiku を呼ばないときを README に書いた。

## 0.11.0 — 2026-10-23

- 修正: 判定（Haiku の呼び出し）に時間制限が無く、API が混んでいるとプロンプトの開始がいつまでも待たされた。hook の持ち時間は `$` の呼び出し中は止まるため、エンジン側でも打ち切られない。`$.model.classify` をやめて `$.model.complete` で呼び、4秒で打ち切るようにした。打ち切ったときは、失敗したときと同じく前ターンの段階を引き継ぐ（`error, kept`）。
- 修正: `/model` で切り替えた直後のターンを、切り替える前のモデルで判断していた（対象外から対象のモデルに替えると最初のターンを振り分けず、逆だと Haiku を無駄に呼んでいた）。`classic.PostModelSwitch` でモデルを知るようにした。
- 修正: 対象外のモデルで `/effort` を打つと、ステータスラインが「(set by /effort)」に変わり、あとで対象のモデルに替えた最初のターンが手動の設定として扱われた。対象外のモデルでは何もしないようにした。
- 修正: `/effort-router` の応答文の対象モデルに Haiku が抜けていた。
- 変更: Haiku の返答は、最初の語を大文字・記号・句読点を無視して照合する（`High.` や `**xhigh**` も読む）。
- 内部: 途中の引き上げの計算を `route.ts` の純粋関数 `raise()` に移し、境界の単体テストを足した。
- 文書: 対象モデルの表記を Haiku 込みにそろえた。判定の呼び出しと時間制限を「仕組み」に書いた。
- 文書: 評価セットを測り直し（36件中32件一致、低すぎる判定は0件）、README の一致率と待ち時間を更新した。

## 0.10.0 — 2026-10-08

- 変更: Haiku 5.5 以降も対象にした。公式ドキュメントで、Haiku 5.5 は Opus 5.5・Sonnet 5.5 と同じく effort を変えてもプロンプトキャッシュが保たれ、既定は medium とされている。判定の基準は Opus 5.5 に合わせたままで、Haiku で妥当かは確かめていない。

## 0.9.1 — 2026-10-08

- 修正: 選択肢を出したあとにツールを呼び、短い文（「結果が届いたらお知らせします」など）でターンを終えると、次の「3」を選択として扱わなかった。0.8 系では前ターンの段階を引き継ぎ、0.9.0 では選んだ案の本文なしで判定していた。`turn.complete` の回答はターンの最後のテキストだけなので、最後のテキストに選択肢がなければ、ターンの途中で選択肢を含んでいたテキストから読むようにした。
- 文書: 選択肢の読み取り元を「回答の全文」から「ターンの最後の回答」に改めた。拾わない書式（見出し、隅付き括弧、区切り記号のない形など）を既知の課題に書いた。

## 0.9.0 — 2026-10-08

- 変更: 20文字未満の入力でも、同意の語だけ（「OK」「はい、進めて」「続けて」など）でなければ Haiku で判定するようにした。これまでは「リポジトリ全体を監査して」のような短い依頼も、前の回答が質問で終わっていなければ前ターンの段階を引き継いでいた。短い入力で Haiku を呼ぶ回数が増え、そのぶん待ち時間（約1秒）が増える。
- 修正: 前の回答に番号付きの一覧があると、「OK」が「前の回答の提案を進める依頼」として渡らず、返事の語に判定が引っぱられていた。同意の返事なら、一覧の有無にかかわらず提案を進める依頼として渡すようにした。
- 修正: 質問のあとの「いや、やめて」のような否定の返事を、提案を進める依頼として渡していた。同意の語だけの返事に限るようにした。
- 評価セットに、一覧のあとの「OK」、短い重い依頼、質問のあとの短い別の依頼、否定の返事の4件を足した（36件）。

## 0.8.1 — 2026-10-07

- 修正: 前の回答の質問に「OK」「はい」とだけ返したとき、承認した作業が重くても low と判定されることがあった。返事の語に判定が引っぱられていたため、Haiku には「前の回答が提案した作業を進める依頼」として渡すようにした。選択肢に無い短い入力と、`AskUserQuestion` への自由記述の回答は、これまでどおり本文で判定する。
- 評価セットに、設計の提案に「ＯＫ」と答えるケースを足した（32件）。

## 0.8.0 — 2026-10-07

- 追加: `/effort-router log clear` で判定ログを消せるようにした。
- 変更: 最初のターンは `$.session.model()` でモデルを確かめ、対象外のモデルなら Haiku を呼ばないようにした（これまでは最初のプロンプトだけ判定が走り、効いていない段階をステータスラインに出していた）。
- 変更: 対象外のモデルでは、ステータスラインに `not routed (<モデル>)` と出すようにした。
- 修正: 回答が CRLF の改行でも選択肢を読み取れるようにした。コードブロックの中の番号付きの行を、選択肢として拾わないようにした。
- 文書: README を、概要・導入・使い方・費用とデータ・仕組みの順に組み直した。費用、待ち時間、Haiku に送るデータ、手元に残るデータを明記した。

## 0.7.0 — 2026-10-07

このリポジトリ（ns-mods）で公開した最初の版です。

- 対象は Opus / Sonnet 5.5 以降と Fable / Mythos 5.1 以降。
- 組み込みの `/effort` で変えた値は、そのターン（ターンの合間なら次のターン）だけ設定どおりに動く。

## 0.6 以前

公開前の版です。主な変更は次のとおりです。

- 0.6: 判定基準を4段階（low / medium / high / xhigh）にし、評価セットの期待値を付け直して、xhigh と low のケースを足した。
- 0.4: 前の回答の選択肢と「質問で終わったか」を、次のターン用の信号として保存するようにした。
- 0.3 まで: 番号での選択と短い返事は、判定を呼ばずに前ターンの段階を引き継いでいた。
